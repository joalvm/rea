# Formato (l10n): fechas, horas, números, moneda

Regla de oro: **el formato lo decide el sistema, no un JSON por país.** `Intl` ya
localiza según el dispositivo. Vive en `modules/l10n` como funciones puras (sin
hook: el idioma no cambia en runtime).

## Qué da el sistema (no se declara)

| Dato | Fuente |
|------|--------|
| Separadores de miles/decimales, nombres y orden de meses-días | `Intl` con el locale del dispositivo |
| Reloj 12/24 h | `getCalendars()[0].uses24hourClock` |
| Divisa de la región | `getLocales()[0].currencyCode` |
| Primer día de la semana | `getCalendars()[0].firstWeekday` |

## Qué sí es código (universal, no por país)

Solo los *presets*: qué CAMPOS muestra cada estilo. Un set único; `Intl` pone los
nombres y el orden de cada locale.

```ts
const DATE_STYLE_OPTIONS: Record<DateStyle, Intl.DateTimeFormatOptions> = {
  long: { day: 'numeric', month: 'long', year: 'numeric' },
  short: { day: '2-digit', month: '2-digit', year: 'numeric' },
};

export function formatDate(value: DateLike, style: DateStyle = 'long', localeOverride?: string): string {
  const locale = resolveFormattingLocale(localeOverride);
  return capitalizeFirst(getDateTimeFormat(locale, DATE_STYLE_OPTIONS[style]).format(toCalendarDate(value)));
}
```

## Locale de formato ≠ idioma de UI

`resolveFormattingLocale` toma el idioma activo + la región del dispositivo
(`es` + `PE` ⇒ `es-PE`), con Perú como mercado por defecto si el sistema no
reporta región. Así moneda/fechas salen locales aunque la copia esté en el idioma
base.

## Anti-patrón (lo que hacía el legacy)

NO crear `formats.json` por país con separadores, nombres de meses, presets de
fecha o reloj. Eso **reinventa `Intl`** y obliga a mantener tablas por cada país.
El SO ya lo hace: basta `Intl` + ajustes del dispositivo.

## Reglas

- `Intl` (memoizado en `intlFormatterCache`) con el locale del sistema; nunca strings de formato a mano.
- Números/porcentaje: reenviar a `Intl.NumberFormat` (separadores = locale). Nada hardcodeado.
- Reloj 12/24 h y divisa: del dispositivo; un único valor de respaldo del mercado principal, no un mapa por país.
- Fechas de solo día (`YYYY-MM-DD`): anclar a mediodía local para evitar saltos de día por zona horaria.
- Sin hook de "re-formatear al cambiar idioma": el idioma no cambia en runtime.
