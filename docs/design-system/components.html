Biblioteca UI mobile de Rea

La biblioteca cubre los bloques necesarios para registrar el ciclo, revisar calendario, leer patrones, ajustar privacidad y resolver estados del producto. Cada componente se piensa para tacto, pantallas pequenas, modo claro/oscuro y datos sensibles.

Navegacion Acciones Formularios Seleccion Check-in Opciones Calendario Datos Feedback Sheets Privacidad

Contrato visual

Superficies suaves, bordes finos, radios consistentes y sombra-susurro que solo redondea.

Contrato tactil

Target minimo 44pt, pressed perceptible, disabled claro y foco accesible.

Contrato semantico

Estado = texto + icono o forma + color. Ningun estado depende solo del color.

01 · Navegacion

App bar y tab bar

La navegacion mobile de Rea se apoya en una tab bar fija con cinco destinos. El app bar identifica la vista actual y no duplica Settings, porque configuracion ya tiene su propio tab.

AppBar
Calendario
  • Altura 56 sin safe area; sumar safe area superior en runtime.
  • El icono derecho representa la vista, no es boton.
  • Sin sombra sticky; separar con hairline o cambio de superficie.
  • Titulo maximo una linea; detalles extensos viven en contenido.
TabBar
  • Activo por color, peso de trazo y label; no usar capsula flotante.
  • Label estable de una palabra. No reordenar tabs por vista.
  • Altura nominal 60; sumar safe area inferior en runtime.
02 · Acciones

Button e IconButton

Variantes
Contrato
  • primary: una vez por vista, accion principal.
  • secondary: accion recomendada sin dominar la pantalla.
  • outline: editar, cambiar o cancelar algo reversible.
  • ghost: accion ligera dentro de un contexto cercano.
  • danger: siempre con copy especifico y confirmacion si borra datos.
03 · Formularios

Field, Input y TextArea

Estados
  • Default, focus, filled, error, disabled y read-only.
  • Label siempre visible. Placeholder solo orienta formato.
  • Error aparece debajo del campo con texto breve y rol accesible.
  • Teclado debe corresponder al dato: fecha, numero, texto o busqueda.

El check-in se organiza por pasos reconocibles. La identidad principal de cada paso es icono, etiqueta y estado visual; la posicion numerica solo pertenece al progreso interno.

06 · Opciones de check-in

Escalas con iconos y lenguaje humano

Para estados graduables, Rea muestra opciones tactiles con icono, nombre y descripcion. El valor numerico puede persistirse internamente, pero no debe ser la marca visual de la opcion.

StressChoiceScale
  • CalmaRespiracion estable, sin tension perceptible.
  • LeveIncomodidad baja, manejable.
  • TensionSe nota en el cuerpo o el animo.
  • AltaCuesta concentrarse o descansar.
  • Muy altaEstado intenso durante buena parte del dia.
  • LimiteNecesita pausa, apoyo o cuidado inmediato.
Contrato
  • La interfaz muestra etiqueta e icono; el valor numerico vive solo en datos.
  • Una opcion activa por pregunta cuando el dato es escalar.
  • Icono + texto + estado selected; no depender de color o numero.
  • Descripcion corta para reducir duda sin convertirlo en test clinico.
  • Opciones equivalentes deben existir para dolor, energia, animo y sueno.

PainChoiceScale

Usar cuerpo/actividad: sin dolor, molestia, dolor moderado, fuerte, muy fuerte, incapacitante.

MoodChoiceScale

Usar rostro/estado: tranquila, sensible, irritable, triste, ansiosa, estable u otro.

SymptomPicker

Seleccion multiple con chips iconograficos: colicos, acne, hinchazon, dolor de cabeza.

09 · Feedback

Alert, Toast, Empty y Skeleton

Registro guardado

Hoy quedo anotado. La prediccion se afinara con tus proximos registros.

Prediccion estimada

Usar una señal compacta de confiabilidad y un texto breve de contexto.

Guardado local completado
Sin registros para este dia Mostrar accion clara, no pantalla vacia.
Contrato
  • Alert: persistente e inline para informacion importante.
  • Toast: confirmacion breve, 3-5 segundos, sin robar foco.
  • Empty: explica estado y propone siguiente accion.
  • Skeleton: refleja estructura real, no barras aleatorias.
10 · Sheets y overlays

Detalle sin perder contexto

Detalle del dia

Bottom sheet para editar registro o ver datos del calendario.

Reglas
  • Se abre desde abajo y mantiene relacion con la vista anterior.
  • Handle visible; cierre por gesto, boton o fondo si no hay perdida de datos.
  • Acciones destructivas no viven solas dentro de sheet sin confirmacion.
  • Altura adaptable: compacta, media o completa segun contenido.
